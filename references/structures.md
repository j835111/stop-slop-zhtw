# 中文 AI 句式套路黑名單

詞彙是表層，句式是深層。AI 即使把禁用詞全換掉，骨架不變還是一眼能認出。這份清單針對句式和篇章結構。

---

## 1. 三件套排比（中文 AI 最強指紋）

把同一個意思用三個相同結構的短語說三遍，是 AI 寫中文時最穩定的發病點。

**典型模板**：
- "A 是 X，B 是 X，C 是 X"
- "既要 A，也要 B，還要 C"
- "為了 A，為了 B，也為了 C"
- "是 A，是 B，更是 C"
- "不僅 A，還 B，更 C"
- "A 也好，B 也好，C 也好"
- "我們要 A，我們要 B，我們更要 C"

**為什麼病**：三件套把資訊密度稀釋成原來的 1/3。三句裡通常只有一句有用，另兩句是結構填充。

**改寫方法**：
1. 保留三句中最有力的一句，刪其他兩句
2. 三句意思真的不同 → 拆成三段，每段把這一點講透
3. 改成非排比的不同句式表達

> **原**：寫作是一種思考，是一種表達，更是一種修行。  
> **改**：寫作就是思考的腳手架。

> **原**：我們要敬畏使用者，要敬畏資料，更要敬畏常識。  
> **改**：使用者回饋不要急著反駁，先認真看資料，再用常識檢驗。（三句話還在，但句式不重複）

---

## 2. 二元對立 / 否定先行

"不是 X，而是 Y" 這類結構是英文版 stop-slop 也提到的 binary contrast，在中文 AI 裡同樣高頻。

**模板**：
- "不是 X，而是 Y"
- "X 不僅僅是 X，更是 Y"
- "與其 X，不如 Y"
- "重要的不是 X，而是 Y"
- "真正的 X 不是 A，而是 B"

偶爾用一次是修辭，連續用就是套路。一篇文章裡出現兩次以上就要警惕。

**改寫**：直接說 Y 是什麼，不用否定 X 做鋪墊。

> **原**：成功不是結果，而是過程。  
> **改**：把"做完"當作終點的人，往往在第三步就放棄了。

---

## 3. 名詞化動詞 + 抽象搭子

把動作變成"動詞 + 名詞"組合。中文比英文更容易染上這毛病，因為中文動詞加"進行/做出/實現"就顯得正式。

**典型搭配**：

| 名詞化寫法 | 改寫 |
|---|---|
| 進行 + 優化 / 改進 / 分析 / 溝通 | 優化 / 改 / 分析 / 聊 |
| 做出 + 選擇 / 決定 / 努力 / 貢獻 | 選 / 決定 / 努力 / 做了什麼具體的事 |
| 實現 + 增長 / 突破 / 轉型 | 漲了 / 突破了什麼 / 轉去做了什麼 |
| 採取 + 措施 / 行動 / 策略 | 怎麼做（寫具體動作） |
| 加以 + 改進 / 解決 / 利用 | 改 / 解決 / 用 |
| 給予 + 支持 / 關注 / 幫助 | 支持 / 關注 / 幫忙 |
| 起到 + 作用 / 效果 | 做了什麼 |
| 發揮 + 作用 / 優勢 | 同上 |
| 形成 + 局面 / 態勢 / 格局 | 寫出實際局面 |

**整段對比**：

> **原**：我們對系統的性能進行了優化，對使用者的回饋做出了響應，並對相關問題加以解決。  
> **改**：我們把首頁載入砍了 3 秒，把使用者提的 17 條回饋討論了一遍，關掉了 5 個老 bug。

---

## 4. 長定語 + "的"字串

中文 AI 喜歡往主語前堆一長串"的"字定語。

**模板**：
- "一個能夠 XX 的 XX"
- "一種基於 XX 的、面向 XX 的、用於 XX 的 XX"
- "在 XX 背景下、由 XX 推動的、具有 XX 特徵的 XX"

判斷標準：一個名詞前的"的"字定語超過 2 層，就要拆。

> **原**：這是一個面向中小企業、能夠幫助使用者在複雜業務場景下高效完成資料分析任務的工具。  
> **改**：這工具給中小企業用，主要功能是做資料分析。複雜場景跑得動，操作不需要培訓。

---

## 5. 抽象主語（虛化主語）

讓"時代 / 科技 / AI / 行業 / 未來 / 歷史 / 現實" 做主語，聽起來宏大其實是逃避——逃避交代到底是誰幹的。

**典型句**：
- "時代的浪潮要求我們 XX"
- "科技正在改變我們的生活"
- "AI 正在重塑工作方式"
- "現實告訴我們 XX"
- "行業的發展呼喚著 XX"
- "未來屬於 XX"
- "歷史選擇了 XX"
- "資料顯示 / 資料告訴我們"（弱化版，但仍要警覺）

**改寫原則**：把抽象主語替換成具體的人 / 團隊 / 數字。

> **原**：AI 正在重塑軟體開發。  
> **改**：我們組三個工程師，過去半年有兩個把日常除錯丟給了 Claude。

> **原**：時代要求每個人都成為終身學習者。  
> **改**：我上家公司四年招進來的同事，沒自學過新東西的，到第三年基本都被邊緣化了。

---

## 6. 戲劇性短句碎片

故意把一句話切成幾個獨立短句，製造節奏。英文叫 dramatic fragmentation。

**模板**：
- "[名詞]。就這麼簡單。"
- "這就是答案。"
- "記住這一點。"
- "[一個詞]。僅此而已。"
- "想清楚了嗎。"

中文裡偶爾用一次有節奏感，但 AI 喜歡段尾用、每段都用，就是套路。

**改寫**：合併成一句完整的話。

> **原**：寫作就是思考。僅此而已。  
> **改**：寫作就是把思考寫下來。

---

## 7. 反問句空轉

用反問代替陳述，故作啟發但其實沒說出更多資訊。

**模板**：
- "這難道不是 XX 嗎？"
- "我們怎麼能 XX 呢？"
- "誰不希望 XX？"
- "你是否也曾 XX？"
- "為什麼 XX？因為 XX。"（自問自答）
- "What if XX？" 的中文翻譯版：「如果我告訴你 XX 呢？」

**改寫**：把反問改成陳述，直接說結論。

> **原**：這難道不是每個產品經理的夢想嗎？  
> **改**：這是產品經理想要的。（或者更具體：這能省掉每週兩小時的對齊會議。）

## 8. 立 flag 式金句收尾

中文 AI 段落收尾最穩的病。每段都試圖升華，每段都來一句"準格言"。

**典型句式**：
- "這，就是 XX 的力量"
- "這，就是 XX 的意義"
- "唯有 XX，方能 XX"
- "或許，XX 才是真正的 XX"
- "XX 永遠在路上"
- "致敬每一位 XX"
- "未來，屬於那些 XX 的人"

**判斷**：把段尾這句刪了，段落還成立嗎？成立就刪。

人寫文章不會每段都升華。讓段落正常結束。

## 9. 總分總八股結構

整篇文章的骨架病。

**典型骨架**：
```
開篇：背景 + 定義 + 重要性
分點 1：首先 ……
分點 2：其次 ……
分點 3：再者 ……
（可選）分點 4：最後 ……
結尾：綜上所述 / 讓我們一起 / 升華金句
```

這是高考議論文 / 公文 / PPT 大綱的結構，**不是自然的文章結構**。

**可替代骨架**：

- **直接開幹**：第一句就是核心結論或具體衝突，後面是論據 / 故事
- **倒三角**：最反常識 / 最重要的放最前，往後越來越細
- **故事線**：按時間 / 因果 / 衝突推進，不分點
- **單點深挖**：一篇只講一件事，把它講透，不湊數

如果分點結構無法避免（如說明文），至少：
- 每一點的開篇句長得不一樣，不全是"首先 / 其次"
- 不要在最後一段加"綜上所述"
- 不要給文章加"金句結尾"

## 10. 價值判斷飽和

每個句子都在評價"這很重要 / 這很關鍵"，但從不說為什麼、對誰。

**典型**：
- "XX 至關重要"
- "XX 是不可或缺的"
- "XX 起到了關鍵作用"
- "XX 具有深遠意義"
- "XX 是 XX 的核心"

判斷標準：評價詞後面是否跟具體場景？沒有就刪評價、要麼補具體。

> **原**：使用者回饋對產品迭代至關重要。  
> **改**：上次重做支付頁是因為 30 多個使用者在客服那罵卡住了——回饋就是這麼用的。

## 11. 假親切敘述視角

強行模擬"朋友談心"的口吻，但 AI 模擬得不準，會出現：

- 用"朋友們 / 家人們 / 寶子們 / 各位"開頭
- 用"我懂你的感受 / 你不是一個人 / 你值得被看見"安慰
- "親愛的讀者，今天我想和你聊聊"
- 突然插入"對了 / 順便說一下"假裝隨性

真人寫談心文章是有具體的"我"和具體的"你"——具體的經歷、具體的對話、具體的場景。AI 寫的"親切"是沒有錨點的空親切。

**改寫**：要麼去掉假親切稱呼，純陳述；要麼補具體的人和事來支撐親切感。

---

## 12. 遠距離敘述者

英文 stop-slop 裡叫 narrator-from-a-distance。中文版表現為：

- 全篇沒有"我"，也沒有具體的人物
- 全是"人們 / 大家 / 我們 / 使用者 / 讀者"這類集合名詞做主語
- 描述事情用上帝視角，永遠是觀察者，永遠不在現場

> **原**：人們在面對壓力時，往往會做出不理智的選擇。  
> **改**：上週我連續加班四天後，把保溫杯裡的水倒進了筆記本鍵盤——我以為那是垃圾桶。

把"人們"換成具體的"我"或"具體的某個人"，文本立刻有重量。

---

## 13. 節奏單調 / 句長趨同

AI 中文輸出的隱性指紋：句子長度方差小，每句字數差不多（一般在 15–25 字區間）。

**自測方法**：把每句的字數列出來。如果連續 5 句的字數都在 ±5 字以內，節奏就是 AI 節奏。

**改寫**：故意打破。把兩句合併成長句，或者把一句拆成兩個短句（不是戲劇性碎片，而是自然停頓）。

> **原**（每句 18 字左右）：他打開電腦準備開始工作。螢幕上顯示著昨天未完成的程式碼。他想了想決定從頭開始寫。  
> **改**：他打開電腦，發現昨天的程式碼自己看了三分鐘都沒看懂——重寫。

---

## 14. 三項列表偏好

只要列點，AI 傾向於列三點。兩點顯得不夠全，四點顯得太多。

如果你發現自己每次列點都列三點，停下來想：

- 真的有三點？還是湊出來的三點？
- 如果只有兩點，就列兩點
- 如果有四點或更多，就列四點或更多
- 如果一點能講清楚，根本別列點

---

## 15. 每段同等長度

段落長度趨同也是 AI 指紋。AI 輸出的段落普遍在 80–150 字，很少有特別短（一行）或特別長（一屏）的段落。

**真人寫作的段落**會有節奏波動：
- 一句話獨立成段，用來強調或轉折
- 一個段落 200+ 字，深入講一件事
- 短段 + 長段交替

**改寫**：檢查段落長度方差。如果全篇段落長度都差不多，主動把某些段落合併或拆開。

---

## 使用說明

這 15 條裡，**1（三件套排比）、3（名詞化）、5（抽象主語）、8（金句收尾）、9（八股結構）**是中文 AI 文本最強的五個指紋。改寫時優先處理這五項，命中率最高。

其餘十項是補充指紋，遇到就處理；找不到不必強求。
